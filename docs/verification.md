# 章を作ったときの検証手順

遊んで確かめる代わりに、章を作るたび（直すたび）に次を必ず行う。結果はプルリクエストに書く。

## 1. 組み立てと点検

```sh
python3 tools/build.py <ゲームid>
```

存在しないアイテム・場所・人物、条件の書き間違い、背景の不足などを見つける。

## 2. 動作テスト

```sh
python3 tests/run.py
```

通しクリア、セーブとロード、手帳、矛盾をつく、作品選択など。新しい章を作ったら、その章を最後まで通すテストを足す。

## 3. 詰み・バグ・行き止まりの文の検証

```sh
python3 tools/verify.py <ゲームid>
```

| 検証 | 内容 |
|---|---|
| 総当たり | 取れる行動をすべて試し、たどり着ける状態を集める。調べきれた章は、どの状態からも章の終わりへ行けるか（**詰み**がないか）を確実に判定する |
| 確率的な詰み検出 | 状態が多すぎて調べきれない章では、ランダムに遊ばせた途中の状態（千数百）から、さらにランダムに遊ばせて章の終わりへ行けるかを試す |
| エラー | 検証中に起きたエラー |
| 行き止まりの文 | 一度も表示されなかった文。たどり着けない場所の文や、条件の順番のせいで出ないヒントが見つかる |

`✗` が出たら直してから出す。

## 4. 物語の矛盾の確認（人が読む）

```sh
python3 tools/verify.py <ゲームid> --times
```

時刻・日付・年が出てくる文の一覧を、設計書（`games/<id>/WALKTHROUGH.md`）の時刻表と突き合わせる。あわせて次を確かめる。

- 人物の年齢と、その人が知っているはずの出来事（生まれる前のことを覚えていないか）
- 同じ時刻に、同じ人が二か所にいないか
- 証言カードの内容が、設計書の手がかり一覧と食い違っていないか
- 犯人だけが目立つ描写になっていないか（設計書の「動機の配り方」）
- 推理に必要な手がかりが、読者への挑戦より前にすべて出ているか

見つかった矛盾は、会話と設計書の両方を直す。
