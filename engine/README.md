# 共通エンジン

推理アドベンチャーを、JSONのシナリオから動かすエンジン。

## フォルダ構成

```
engine/            エンジン本体（engine.js・engine.css・template.html）
games/<id>/src/    シナリオ（game.json・章ごとの <章id>.json・bg/ の背景画像）
games/<id>/index.html   組み立てたゲーム（tools/build.py が作る。直接編集しない）
tools/build.py     組み立てと点検
tests/run.py       動作テスト
```

## 組み立てとテスト

```sh
python3 tools/build.py shiomi-port          # 組み立て（点検も行う）
python3 tools/build.py shiomi-port --check  # 点検だけ
python3 tools/build.py tests/fixtures/mini && python3 tests/run.py
```

組み立てると `games/<id>/index.html`（エンジンとシナリオ入り）と `games/<id>/bg/*.webp`（背景）ができる。開くだけで遊べる。

起動時の読み込み画面で、背景をすべてと、ゲームで使う文字のフォント（Google Fonts）を先に読み込む。そのため、遊んでいる間は通信しない。`--inline` を付けると背景もHTMLに埋め込み、1ファイルにできる。

## 背景画像のルール

| 項目 | ルール |
|---|---|
| 置き場所 | `games/<id>/src/bg/<名前>.jpg`（png・webpも可）。場所の `bg` に `<名前>` を書く |
| 名前 | 英小文字・数字・ハイフン（例：`library-night`） |
| 大きさ | 16:9で、幅1280px以上。組み立て時に幅1280pxのWebP（画質80）に変換される |
| 1枚に1場面 | 何場面も並べた一覧画像は使わない（切り出すと画質が落ちる） |

**AIで作った画像の点検**（取り込む前に確かめる）
- 看板や張り紙の文字が正しいか（例：「汐見警察署」が「汐見事業署」になっていないか）
- 場面の意味が変わっていないか（例：雀荘が、花で飾られた葬儀場に見えないか）
- 時代が合っているか（昭和の場面にスマホや高層ビルが写っていないか）
- 人物の顔がはっきり写っていないか（背景には人を入れず、人物は名前タグで表す）
- 同じ作品の背景どうしで、絵柄と色味がそろっているか

## game.json

| キー | 内容 |
|---|---|
| `id` | ゲームのid。セーブの保存先とクリア記録に使う |
| `title` | ページのタイトル |
| `hub` | 作品選択ページへの相対パス（例：`../../index.html`）。あるとタイトル画面に「作品選択へ」が出る |
| `start` | 最初の章のid |
| `chapters` | 章のidを順番に並べた配列。`src/<id>.json` を読む |
| `titleScreen` | `eyebrow`・`title`（`<br>` 可）・`lead` |
| `prologue` | あらすじ画面。`paragraphs`（HTML可）・`cast`（`[名前, 説明]` の配列）・`button`。なければ省略 |
| `items` | `{id: 表示名}` |
| `people` | `{id: {name, short}}`。`short` は「見せる」「推理」で使う短い名前 |
| `assistant`・`assistantHint` | 助手の人物idと、そのヒントの文（`{name}` が使える）。助手に聞くと、今いる場所でまだ大事な話（証言カードになる話）を聞いていない人がいれば、ふだんのヒントより先にこの文で教える |
| `endings` | `{id: {bg, place, small, pages, finalBg, finalPlace, finalSmall, ranks, result}}` |

`result` では `{turns}`（行動回数）・`{miss}`（まちがい回数）・`{rank}`・`{time}`（プレイ時間）が使える。`"clear": false` にすると、クリアの記録（作品選択の⭐️）を付けない（試作の途中までの終わりなどに使う）。`ranks` は上から順に条件を見て、最初に合ったものの `label` になる。

## 章（<章id>.json）

| キー | 内容 |
|---|---|
| `id`・`label`・`title` | 章のid、「第一章」のような番号、章の題 |
| `card` | `false` にすると章のはじめの題字画面を出さない |
| `start` | `{loc, text}`。章のはじめの場所と文 |
| `locations` | `{id: {name, bg, unlock, people, objs, arrive}}`。`people` には `{"id": "...", "if": "条件"}` も書け、場面によって人を出入りさせられる。`unlock` は行けるようになる条件（満たした瞬間に「○○に行けるようになった」と自動で通知される）、`objs` は `{id: 表示名}` |
| `onMove` | 移動するたびに確かめるルールの配列（当てはまるものすべてを実行） |
| `triggers` | 行動のたびに確かめ、条件がそろったら1つだけ動くルール（宴の始まりなど）。`do` に同じトリガーが二度動かないためのフラグを入れる |
| `events` | `{id: {bg, place, pages, do}}`。何ページか続く場面 |
| `talk` | `{人物id: 返事}` |
| `show` | `{人物id: {アイテムid: 返事}}` |
| `look` | `{調べるものid: 返事}` |
| `puzzles` | 番号入力の謎解き。`{id: {length, answer, label, prompt, display, success, fail, cancel}}` |
| `accuse` | 犯人の指名。`{suspects, culprit, required, missingText, ending, wrong, noneText}`。選べるのは `suspects` のうち一度でも話を聞いた人だけ（だれもいなければ `noneText`）。犯人を選んだが `required` がそろっていないときは `missingText`（`{name}`・`{missing}` が使える）。`{missing}` で足りない証拠を並べると答えが分かってしまうので、ふつうは使わず、まだ疑いの晴れていない人と同じ文にする |
| `talkDefault`・`showDefault` | 返事がないときの文。`{name}` が使える |
| `recap` | 「これまでの話」。章のはじめと「つづきから」で表示し、手帳の「これまで」タブにも残る |

### 返事の書き方

返事は4通りで書ける。

```jsonc
"文だけ"
{"text": "文", "do": ["効果", ...]}               // ルール1つ。"if" を付けると条件つき
[{"if": "条件", "text": "..."}, {"text": "..."}]  // 上から見て最初に条件が合うもの
{"seq": [{"text": "1回目"}, {"text": "2回目以降"}]} // 話すたびに次へ。最後はくり返す
```

`text` が `名前「…」` の形なら、名前が話し手のタグとして表示される。

ルールに `"card"` を付けると、その返事が**証言カード**として捜査手帳に残る。`"card": true` なら文をそのまま、`"card": "要約"` なら要約を記録する。カードには「誰が・どこで・何を言ったか」という事実だけを書き、「だから怪しい」のような結論は書かない。

### 話題を選んで聞く

`talk` の値を `{"topics": {話題id: 返事, ...}}` にすると、「聞く」で人を選んだあとに話題を選べる。話題の名前は game.json の `topics`（例：`{"ima": "いまのこと", "kuga": "創業者のこと"}`）。いま返事がない話題は出ない。`talked:人物` はすべての話題を合わせた回数なので、「1回目だけの挨拶」はフラグで書く。

### 助手のヒント（段階式）

助手（game.json の `assistant`）の返事のルールに `"hints": [ぼかした文, …, はっきりした文]` を書くと、同じ段階で聞くたびに次の文になる。助手に話題がある場合、`hintTopic` の話題がヒントになる。今いる場所に、まだ証言カードになる話を聞いていない人がいれば、その人について1回だけ先に教える。ヒントを聞いた回数は `{hints}`（結果画面）と `var:hints`（条件）で使える。

### 取材ノート

ルールに `"note": "要約"` を付けると、手帳の「取材ノート」タブに残る（game.json に `notes: {tab, lead}` があるときだけタブが出る）。件数は `var:notes`・`{notes}` で使える。

### 条件

| 書き方 | 意味 |
|---|---|
| `has:capsule` | アイテムを持っている |
| `flag:sent` | フラグが立っている |
| `var:wait>=1` | 数の比較（`>=` `<=` `==` `!=` `>` `<`）。比較なしなら0より大きい |
| `talked:haru>=2` | その人に話した回数（話題をすべて合わせた数） |
| `here:study` | 今その場所にいる |
| `!`・`&&`・`||`・`( )` | 否定・かつ・または・かっこ |

### 効果

| 書き方 | 意味 |
|---|---|
| `give:x`・`take:x` | アイテムを渡す（入手の通知が出る）・取り上げる |
| `flag:x`・`unflag:x` | フラグを立てる・下ろす |
| `set:x=0`・`inc:x` | 数を入れる・1増やす |
| `miss` | まちがいを1回数える |
| `toast:文` | 画面の上に通知を出す（同じ文は1回だけ） |
| `goto:場所id` | 場所を移る |
| `puzzle:id` | 番号入力の謎解きを開く |
| `chapter:章id` | 「つぎへ」のあと、その章を始める |
| `event:id` | 章の `events` の場面を見せる（何ページか続く。最後に `do` を行う） |
| `card:人物id:文` | 証言カードを残す（人物なしは `card::文`） |
| `ending:id` | 「つぎへ」のあと、エンディングへ |

## 矛盾をつく

証言カードを2枚選んで「この2つは食い違う」とつきつける仕組み。手帳の「証言カード」タブに「矛盾をつく」ボタンが出る（章に `contradictions` があり、カードが2枚以上あるとき）。

```jsonc
// 証言カードに cardId を付ける
{"text": "片桐「薬には関わっていない」", "card": "薬には関わっていないと言った", "cardId": "katagiri_lie"}

// 章の contradictions
"contradictions": [{
  "id": "lie",                                    // 解くと flag:contra_lie が立つ
  "pairs": [["katagiri_lie", "haru_med"]],        // 正解の組み合わせ（順番は問わない。複数書ける）
  "if": "here:law",                               // つきつけられる条件（相手がいる場所など）
  "text": "片桐「…ああ、受け取りに行ったよ」",    // 正解のときの文
  "do": ["toast:片桐のうそを崩した"],
  "card": "薬を受け取りに行ったと認めた",          // 認めた内容を新しい証言カードにする（cardId・p も書ける）
  "p": "katagiri",                                // そのカードを言った人
  "breaks": ["katagiri_lie"],                     // 「崩した」印を付けるカード（省略すると2枚とも）
  "notYet": "本人に突きつけましょう",               // 組み合わせは正しいが if を満たさないとき（ミスにならない）
  "doneText": "もう崩しましたよ"                    // 解いたあとにもう一度つきつけたとき
}],
"contradictWrong": "その2つは食い違っていないようです"  // まちがいのとき（ミス1回）
```

正解すると、崩したカードには手帳で「崩した」の印と取り消し線が付き、認めた内容が新しい証言カードになる。`text` の最後で、助手に次の手がかりを示させると、何をすればいいか分かりやすい。

## 捜査手帳

画面下のコマンド「手帳」から開く。新しい証言カードがあると、数がバッジで出る。

| タブ | 内容 |
|---|---|
| 証言カード | `card` の付いた返事。☆でピン留めでき、ピン留めだけに絞り込める |
| 会話ログ | 表示した文すべて（新しい順）。ことば検索、話した人・場所・章で絞り込み、ピン留め |
| もちもの | 持っているアイテム |
| メモ | 自由に書けるメモ。ゲームの進み方には関係しない |
| これまで | 今の章までの `recap` |

## セーブ

- **オートセーブ**：行動するたびに自動で保存。タイトルの「つづきから」はこれを読む
- **章のはじめ**：章が始まるたびに保存。ロード画面から戻れる
- **スロット1〜3**：メニューから手動で保存

保存先はブラウザの localStorage（`mg:<ゲームid>:...`）。クリアしたゲームは `mg:cleared` に記録される（タイトル画面の⭐️に使う）。

## 第二作で足した機能

| 機能 | 書き方 |
|---|---|
| 章ごとの助手 | 章に `"assistant": "人物id"`、`"assistantHint"`、`"hintTopic"` を書くと、game.json の設定より優先する。`"assistant": null` で助手なし |
| 考える | 章に `"think": ルール`（`hints` も使える）を書くと、コマンドに「考える」が出る。まず `thinkHint`（`{name}` 入り）で聞き残しを教え、なければ think の文。助手のいない章（倒叙の犯人視点など）のヒント役 |
| 選択式の問い | 章に `"choices": {id: {prompt, label, options: [{label, text, do}]}}`。効果 `choice:id` で出す。まちがいは `do` に `"miss", "choice:id"` で選び直し。選ぶ前に「手帳を見る」で資料を見返せる |
| 資料 | game.json に `"docs": {id: {title, text}}`。効果 `doc:id` で手帳の「資料」タブに加わる（表や数字を見ながら謎を解く用） |
| 手帳の名前 | game.json か章に `"nbTitle"`（既定は「捜査手帳」） |
| 答えの幅 | 謎解きに `"answers": ["1740", "1745", "1750"]` を書くと、answer のほかにも正解にする（計算の丸めの違いを許す） |
| 視点の切り替え | 章に `"freshNotebook": true` を書くと、その章のはじめに証言カード・もちもの・資料を空にする（会話ログとメモは残る）。倒叙で犯人側から刑事側へ移るとき用 |
| 記事の検索 | 章に `"searches": {id: {label, prompt, placeholder, entries: [{keys: [ことば…], text, do}], none}}`。効果 `search:id` で入力欄が出る。入力に keys のどれかが含まれれば、そのルール（`if` も使える）。検索した回数は `var:searches` |
| 日数 | 決まった仕組みはない。`inc:day` などで数える。エンディングの result には `{day}` のように、どの変数（var）でも出せる |
| 前の作品の条件 | game.json に `"requires": [{"id": "作品id", "title": "題"}]`。その作品をクリアしていないと、タイトル画面に「〜をクリアすると遊べます」とだけ出る。作品選択（hub.json の games）では `"requires": "作品id"` |
